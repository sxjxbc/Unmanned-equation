# 旧版失效保护与启动兼容修正

适用入口：`acceleration_event.launch`。仍按原方式满足定位和路径条件后自动开始控制，没有新增人工发车话题，也不要求车辆先移动。

## 启动与停车行为

- 等待期间不发送新的停车编码，缺数据只提示等待原因；数据恢复后可重新判断就绪。GPS位置不变不作为锁存故障，不要求三帧确认或独立轮速。
- 新增必要条件：定位、IMU、路径及规划器道路状态在有效期内。缺少这些输入时不会绕过检查强行启动。新版规划器与控制器必须成套部署。
- 从第一次实际进入控制开始计为运行，即使车辆仍停在起点，也开始检查超时。这保留原自动启动语义；如需“直到物理发车才布防”，必须另接可靠发车信号。
- 运行中持续超时、找不到前瞻点、控制计算异常或CAN发送失败，锁存停车原因，按现有协议持续发送 `raw=2000`；不再通过简单 return 代替停车。终点停车也先于路径计算处理。
- 停车锁存后需人工确认、停止车辆，再重启控制节点。停车原因不会被随后出现的错误覆盖。重启不能保证解除VCU内部锁存，仍须按车端协议操作。

## 参数与边界

| 启动参数 | 默认值 | 说明 |
|---|---|---|
| guard_pose_timeout | 0.8秒 | 定位和IMU有效期；定位含源时间年龄，零时间戳兼容接收时间 |
| guard_path_timeout | 1.0秒 | 路径发布与源时间年龄预算 |
| guard_road_timeout | 1.0秒 | 最后有效拟合所依据的地图观测时间预算 |

这些是可配置的首轮值，尚未按车机实测延迟标定。短于门限的间断继续沿用已有控制算法，不会因单个周期缺数据立即停车；这并非经过完整运动补偿的新保持算法。

主位姿改为每个20Hz控制周期选取最新缓存，去掉原1Hz刷新瓶颈；回调与控制通过锁避免读取半份状态。未修改PD增益、前视距离、转角上限、转角步长及正常CAN编码。

地图 `ConeArray.header.stamp` 现在表示最后有非空有效雷达检测的源时间；零源时间兼容接收时间。维护地图、空帧和重复源时间戳不刷新该时间。规划器将拟合结果的支持时间向下游传递；控制器计入状态消息传输年龄。

限制：该时间是整张地图最近一次非空检测的时间，并非每个锥桶最后被观测的时间；杂点或单侧观测仍可能让旧地图保有新时间。此次没有实现锥桶身份追踪，不能保证所有几何错误都被识别。此前分析的坐标系混用、斜率限制和控制响应调参也尚未在本次修改中处理。

## 车机使用

将整个更新后的 acceleration_event 包部署到车机，重新构建并 source：

```bash
cd ~/nrt_ws
source /opt/ros/melodic/setup.bash
catkin_make -j2
source devel/setup.bash
roslaunch acceleration_event acceleration_event.launch
```

传感器按原方式启动。在另一个已source终端查看：

```bash
rostopic echo /control/legacy_status
```

- `state=waiting`：启动前可恢复的等待，查看 `waiting_for`；例如 road_stale 要检查新规划器与雷达观测，而不是先放宽门限。
- `state=running`：已进入原控制逻辑。
- `state=stopped`：锁存停车，查看 `stop_reason` 和 `stop_udp_sent`。

使用先前的 `run_diagnostics.launch mode:=legacy` 可同步保存该状态及停车原因。诊断节点的 `/diagnostics/run_active` 只开关诊断报警，不控制本控制器是否启动。

部署前应在车辆禁止运动的条件下核对VCU确实识别 `raw=2000`，再验证输入中断、恢复、停车锁存及节点重启流程。离线发送成功测试不能证明实车制动效果；本工作区没有完成车机ROS构建或实车验收。
