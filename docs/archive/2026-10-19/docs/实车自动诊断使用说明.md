# 实车自动诊断

诊断程序旁路订阅，不发送 CAN、不修改转角、不自动停车。适配 ROS 1 / Python 2.7 和 Python 3。车机尚需构建和话题联调；本机测试不等于实车验收。

## 启动

在车机工作区编译一次，路径替换成实际路径：

```bash
cd ~/nrt_ws
source /opt/ros/melodic/setup.bash
catkin_make -j2
source devel/setup.bash
roslaunch acceleration_event run_diagnostics.launch mode:=legacy
```

另一个终端照常启动原传感器和控制程序。旧版 acceleration_event.launch 对应 mode:=legacy；新版 acceleration_lidar.launch 对应 mode:=lidar。诊断节点不会启动这些程序。

程序启动后立即记录数据，但默认不报警。准备发车时，在已 source 工作区的终端执行：

```bash
rostopic pub -1 /diagnostics/run_active std_msgs/Bool 'data: true'
```

停车后关闭本次检测，避免把正常静止误报为定位冻结：

```bash
rostopic pub -1 /diagnostics/run_active std_msgs/Bool 'data: false'
```

也可以用 `run_active:=true` 随启动开启判断；等待发车和停车阶段会产生静止疑点。无需静止疑点时务必及时关闭判断。

## 查看结果

终端输出新出现的异常；实时完整结果：

```bash
rostopic echo /diagnostics/run_status
```

默认目录 `/tmp/run_diagnostics/日期时间/`：

- `evidence.jsonl`：每条输入的 ROS 接收时间、原始消息时间及数据，包含全部雷达锥桶、地图锥桶、路径点、GPS、位姿四元数、IMU 航向、转角和融合状态。每 0.2 秒刷新文件。
- `report.json`：异常首次时间、出现次数（按连续异常段计数）、最近证据和判断限制。运行期间每 0.2 秒覆盖更新，Ctrl+C 退出时再次保存。

跑完将整个日期目录复制保存，`/tmp` 可能随重启清理。也可启动时用 `log_dir:=/home/你的用户名/run_diagnostics` 指定持久目录。点云簇数量大时留意磁盘空间。

## 异常含义与排查顺序

| 代码 | 判断与下一步 |
|---|---|
| MISSING_* / STALE_* | 从未收到或超过 0.7 秒没有收到有效数据，检查对应节点和话题；该阈值可用私有参数 timeout 调整 |
| BAD_STAMP_* / ZERO_STAMP_* | 接收仍正常，但源时间过期、超前或为零；检查驱动时间戳和主机时钟 |
| INVALID_* | 存在非有限数值、错误 JSON 或无效经纬度 |
| POSITION_STATIC_GPS / POSITION_STATIC_POSE | 约 3 秒内位置范围小于 5 厘米，仅在确认车辆实际移动时支持定位冻结；停车或低速蠕行可能触发 |
| EMPTY_LIDAR | 感知消息在发，但没有锥桶；结合原始记录判断感知丢失 |
| EMPTY_MAP / EMPTY_PATH | 旧版地图或规划结果为空 |
| LIDAR_REJECTED | 融合控制器报告几何拒绝、等待时间对齐或观测过期，证据中保留具体原因 |
| CONTROLLER_STOP | 融合控制器已经锁存停车原因，例如 road_stale、pose_stale、finish |
| VEHICLE_OUTPUT_DISABLED | 融合控制器为影子模式或未开启实车输出；旁路运行时这是预期状态 |
| UDP_SEND_NOT_CONFIRMED | 融合控制器报告本次发送未成功，检查其停止原因和通信 |
| STEERING_NEAR_LIMIT | 连续约 3 秒转角指令绝对值均不小于 0.48 rad，疑似持续饱和；仅适用于现有 0.50 rad 上限配置 |
| CLOCK_REWIND | ROS 时间回退，已清空历史窗口重新检测 |

先看数据缺失、源时间错误，再看位置冻结，最后看几何拒绝和转角。报告保留异常时间，避免把冲出赛道后的丢锥桶误当作最初原因。

## 判断边界

静止判断依赖人工开启跑动阶段，程序没有独立轮速证据，不能单凭 GPS 不动认定 GPS 坏了。IMU 使用本项目驱动的 `orientation.z=航向角度` 协议。

旧版不发布内部控制状态，诊断只能观察其输入、路径和转角，不能直接确定内部是否进入 global_fallback；原控制 CSV 仍应一起保存。新版通过 `/control/lidar_status` 提供更精确证据。

转角话题表示软件输出，不代表实际车轮角度；UDP 成功也不证明 VCU 已收到。当前没有实测车轮转角、独立速度和 VCU 回执接口，因此不自动断言转向反了、执行器失效或 PID 不合适。需要这些结论时应接入对应反馈后再判断。

该节点提供可追溯故障证据和疑点，不能保证自动定位所有根因，不能代替原有急停和人工接管。
