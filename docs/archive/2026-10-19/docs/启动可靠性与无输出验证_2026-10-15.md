# 启动可靠性与无输出验证

本次补齐旧版ROS验证入口，目的是在没有实车时先检查“初始化等待后能进入控制”，不是证明实车闭环或VCU已通过验收。

## 已修改

- 原 `acceleration_event.launch` 新增 `enable_vehicle_output` 与 `enable_visualization` 开关，均默认true以保留原实车入口行为。正常启动条件、PID、前视、转角限制与CAN编码不变。
- 输出false时旧控制器不创建CAN客户端/socket，不发布 `/control/steering` 或 `/fssim/cmd`；候选结果发布到 `/control/legacy_candidate_steering`。故障停车、正常运行和退出均共用被禁用的输出资源。
- 建图显示false时直接执行 `rospy.spin()`，不创建OpenCV窗口。仍需能导入cv2与NumPy。
- `validation.launch` 固定关闭输出与显示，移除不受主入口支持的旧参数；默认不启动模拟源、不启动真实传感器，默认使用真实时间。
- `live_mapping_check.launch` 固定关闭输出与显示，真实传感器改为显式 `start_sensors:=true` 才启动。它不代替实车控制入口。
- 新增 `validation_inputs.py`：10Hz持续发布静止GPS、项目度数约定的IMU及两组锥桶；只允许在隔离测试中使用，不与真实传感器混用。
- 修复 `smoke_ros_validation.py` 的Python3字节输出解析与节点名查找；使用独立本地ROS master、模拟输入、无输出入口，等待状态达到running并保存状态和启动日志。

## 本机验证结果

73项选定离线测试通过，新增5项覆盖真实控制器构造函数的输出资源禁用、故障/退出无输出、原输出入口保留、建图无显示分支及launch参数兼容。测试只用传输替身，不打开实际车辆socket。

结果位于 `exports/startup_validation_20261015/report.json` 和 `tests.txt`。语法检查及launch XML检查通过。现有控制参数与算法方法未变。

本机没有找到roscore或catkin_make，WSL可用性检查失败；没有安装Linux/ROS或运行真实ROS集成测试。验证入口和脚本已准备，但不能声称其在目标环境已通过。

## 后续在Ubuntu/ROS环境执行

先确认实际ROS和Python版本。若确为原Melodic环境，工作区按实际路径替换：

```bash
source /opt/ros/melodic/setup.bash
cd ~/nrt_ws
catkin_make -j2
source devel/setup.bash
python src/acceleration_event/scripts/smoke_ros_validation.py
```

最后一条会创建独立测试master、启动模拟数据与旧版节点，退出后关闭测试进程，不使用真实CAN。脚本成功应打印 `PASS: synthetic stationary startup reached running; vehicle command topics absent`，并输出日志目录，目录中有 `startup_status.json`、master与节点日志。

失败时先查看nodes.log：依次排查Python导入、自定义消息、包路径、参数、各输入是否到达和时间是否正确。不要直接放宽门限或关闭运行保护。模拟输入默认外参匹配当前launch，如以后修改外参，必须同步模拟源。

不能把 `state=running, enabled=false` 理解为已经允许真实车辆输出。它只证明无输出模式下程序完成就绪；原实车入口仍默认输出true，切勿混用入口或在已有真实控制master中启动模拟源。
