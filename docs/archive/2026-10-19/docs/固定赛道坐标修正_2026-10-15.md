# 固定赛道坐标修正

适用旧版入口 `acceleration_event.launch`。本次修复中心线参考系混用与车体偏航误触发道路斜率保护，没有部署到车机或向车辆发送指令。

## 改动

- 新增 `src/track_frame.py`：无ROS、NumPy依赖的固定平面参考系和锥桶配对函数。
- 地图M仍是原GPS原点与初始车头方向定义的map。固定赛道T原点取首次有效配对时的车辆地图位置，X轴取该锥桶排法线中朝向初始车头的一侧，Y轴遵循原代码的右侧正方向意图。原点不强制在中心线上，中心线用 `d=k*s+b` 表达。
- 只需一组完整左右锥桶即可建立参考，保留自动启动和静止启动；没有新增轮速、人工发车或多帧确认要求。首次道路方向假设若被两排几何拒绝，允许下一次观测重新建立，不在等待阶段永久锁死。
- 候选窗口、排间距去重、拟合、截距限步及历史滤波全部使用T。车头转动不会改变这些历史参数的参考系。斜率0.06约束道路相对固定T的变化，而不是道路相对当前车头的角度。
- 真正超限的固定道路斜率拒绝整次估计，不再强留旧斜率后将角度误差挤进截距。重复拟合同一个观测不会反复积分滤波，也不会刷新有效观测时间。
- 生成路径时用车辆当前T坐标与固定中心线求回归偏移；沿T生成后转换到map。保留单组12米/两组6米渐变、1.5米横向偏移上限及原路径平滑设置。
- `/planning/legacy_road_status` 增加 `frame_origin`、`frame_yaw`、`k`、`b`。旧控制器使用这一份固定中心线，每周期正确转换到当前车体，保留原局部目标±1米限幅与目标混合权重。它不再从地图重复拟合另一条带有历史车体缓存的中心线。
- 控制器局部目标仍采用原0.35秒支持期限；超期退回规划路径。上次加入的定位/IMU、路径/道路参考超时与运行中停车锁存继续有效。

## 保持的起步与控制行为

正常静止不判定位冻结；等待缺数据可以恢复。条件齐备后仍自动进入控制，不等物理发车信号。进入控制以后即开始检查运行故障，即使车辆尚未实际移动。

PID、控制误差滤波、前视距离、转角上限/步长、正常和停车CAN编码、启动文件配置均未改动。相比原来的局部估计，控制器现在消费规划器估计，因此输出可能改变；保持参数不代表整体响应完全不变。

规划器、控制器与新helper必须成套更新。新控制器收到不含固定几何字段的旧状态消息时不会完成道路就绪检查，应检查部署版本，不应关闭保护强行起步。

## 离线验证

重复执行（本机Python3）：

```bash
python src/acceleration_event/scripts/validate_track_frame.py
```

结果：`exports/track_frame_validation_20261015/report.json` 和 `tests.txt`。68项选定测试通过，其中12项是本次新增几何/节点测试，56项是失效保护、融合链路与诊断回归。验证脚本也对照修改前备份检查PID、滤波、前视、CAN方法与launch配置未变。

新增测试直接执行生产规划器、控制器方法和几何helper，覆盖静止单排起步、无完整配对后恢复、±10度车头方向、横移、连续经过后续锥桶排、整体旋转、错误道路方向拒绝、观测保持与超时、规划状态传输到控制器及前瞻目标。

测试中的位姿是预设输入，不是车辆动态模型；连续路径正确不等于实车闭环稳定。测试未使用ROS通信、socket或车辆。未运行目标机Python2.7、catkin构建、rosbag回放或实车验收，也未宣称历史全部测试均通过。

## 已知限制

- 首排方向依赖真实锥桶配对和安装外参；单排方向可能受摆放误差影响。保留单排即可起步是为兼容原启动能力，不是已验证的高置信标定。
- 初始化配对窗口仍相对初始车头判断，严重歪摆、错配可能无法建立正确参考。并未通过放宽几何门限绕过此问题。
- 地图有效观测时间仍是整图最近非空雷达检测时间，没有逐桶身份与最后观测时间。杂点刷新旧地图的边界问题仍存在。
- GPS/IMU不可信、地图漂移、雷达左右/安装角、车辆参考点与外参是否一致、VCU角度方向及真实转角仍需后续实测。
- 短时缺观测期间固定道路几何可正确随当前位姿转换，但定位本身错误时仍可能产生错误目标；超时保护不能识别所有“数值看似有效”的错误。
- 没有调整原控制增益、速度、目标限幅和长距离渐变，也没有证明它们适合真实车辆动态。
